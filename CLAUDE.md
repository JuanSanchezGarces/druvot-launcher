# Druvot Launcher — Claude Reference

Electron-based game launcher for the Druvot OT server. Players download this once; it auto-updates the OTClient files and launches the game.

## Stack

- **Electron 35** — desktop app framework
- **extract-zip** — zip extraction (only runtime dependency)
- **electron-builder** — packages the app into a Windows NSIS installer (publisher name "Druvot", set via `package.json`'s `author`/`build.win.publisherName` — not code-signed)
- All network I/O uses Node.js built-in `https` module (no axios/fetch)

## Project structure

```
src/
  config.js          — all configurable values (GitHub owner/repo, URLs, window size)
  main.js            — Electron main process: update engine, download, launch
  preload.js         — contextBridge: exposes launcher API to renderer securely
  renderer/
    index.html       — UI layout (frameless window with custom titlebar)
    renderer.js      — IPC event wiring, DOM updates
    style.css        — dark gold theme (900×500px fixed)
assets/
  logo.png           — shown in titlebar (bundled, requires a launcher rebuild to change)
  background.png     — shown behind the changelog panel (ALSO deployed to the VPS via deploy.ps1 — remotely updatable, no rebuild needed)
scripts/
  generate-manifest.js  — run locally before each release to produce manifest.json
  deploy.ps1            — SCPs manifest.json, changelog.json and background.png to the VPS
changelog.json       — edit manually to add entries; committed to master branch, deployed via deploy.ps1 (NOT served from git/GitHub — see "Hosting" below). Supports simple markup in `changes[]` strings: `# Title` (heading), `**bold**`, `- item` (bullet), `  - item` (2+ leading spaces, sub-bullet), `""` (spacer)
manifest.json        — auto-generated by generate-manifest.js; committed to master branch, deployed via deploy.ps1. Also holds the background image's `url`/`hash`
```

## How the update flow works

On every launch, `main.js` runs `runUpdateFlow()`:

1. Fetches `manifest.json` from the VPS (`config.MANIFEST_URL` = `https://druvot.com.br/launcher/manifest.json` — NOT GitHub; see "Hosting")
2. Fetches `changelog.json` from the VPS the same way (failure is non-fatal)
3. Sends the changelog to the renderer, and kicks off a non-blocking background-image update (`updateBackground()`) — downloads/caches/hash-verifies `manifest.background` if present, silently keeps the last-known-good image on any failure (missing field, network error, hash mismatch)
4. Compares `manifest.clientVersion` against `version.json` in `app.getPath('userData')`
5. If versions match and `findClientExe()` returns a path → **ready to play** (no download)
6. If update needed → checks no `otclient*.exe` process is currently running (`isClientRunning()`); if one is, aborts immediately with an error telling the player to close the game first (prevents `extractZip` hanging on a locked, already-running exe)
7. Downloads `manifest.download.url` (the release zip) with streaming progress
8. Verifies SHA-256 hash of downloaded zip
9. Re-checks `isClientRunning()` right before extracting (covers the case where the player opened the game mid-download)
10. Extracts zip to `CLIENT_DIR = AppData/Roaming/druvot-launcher/client/`
11. Writes new version via `writeState()` (merges into existing `version.json` rather than overwriting — preserves `backgroundHash`)

## Client exe detection (`findClientExe`)

The zip may extract with a root subfolder (e.g. `Druvot\`). `findClientExe()` searches `CLIENT_DIR` and one level of subdirectories for these names in order:

1. `otclient_dx_x64.exe` (preferred — DirectX)
2. `otclient_gl_x64.exe` (fallback — OpenGL)
3. `otclient.exe`

The game is spawned with `cwd` set to the exe's own directory so it finds its assets correctly.

## Key paths (on player's machine)

| What | Path |
|---|---|
| Extracted client | `%APPDATA%\druvot-launcher\client\` |
| Installed version + backgroundHash | `%APPDATA%\druvot-launcher\version.json` |
| Cached background image | `%APPDATA%\druvot-launcher\background.png` |
| Temp download (client) | `%TEMP%\druvot-client.zip` |
| Temp download (background) | `%TEMP%\druvot-background.png` |

## manifest.json format

```json
{
  "clientVersion": "1.0.0",
  "download": {
    "url": "https://github.com/JuanSanchezGarces/druvot-launcher/releases/download/client-v1.0.0/client.zip",
    "hash": "<sha256 of client.zip>",
    "size": 386000000
  },
  "background": {
    "url": "https://druvot.com.br/launcher/background.png",
    "hash": "<sha256 of background.png>"
  }
}
```

`background` is optional — if absent or its hash doesn't verify, the launcher just keeps showing whatever background it already has (bundled default or previously cached).

## changelog.json format

```json
[
  {
    "date": "2026-05-06",
    "version": "v1.0.0",
    "changes": [
      "# Novidades",
      "**Sistema de dungeons implementado**",
      "  - Detalhe do sistema",
      "- Lançamento do servidor!"
    ]
  }
]
```

Entries are displayed newest-first in the launcher UI. Add new entries at the top of the array. Markup syntax is documented above in "Project structure". Only renders correctly on launcher builds ≥ `launcher-v1.0.0` — older builds show the raw characters as plain text (harmless).

## Workflow: releasing a client update

```bash
# 1. Zip the OTClient folder → client.zip
# 2. Generate manifest (reads GITHUB_OWNER/REPO from src/config.js)
node scripts/generate-manifest.js <version> C:\path\to\client.zip

# 3. Edit changelog.json (new entry at top of array), then deploy manifest + changelog + background to the VPS
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1

# 4. Commit manifest.json and changelog.json to git (record-keeping — NOT what makes them live, deploy.ps1 already did that)
git add manifest.json changelog.json
git commit -m "chore: client v<version>"
git push

# 5. Upload zip to GitHub Release (no 25MB web UI limit via CLI)
Copy-Item C:\path\to\client.zip C:\TFS\client.zip
gh release create client-v<version> C:\TFS\client.zip --title "Client v<version>" --notes "" --repo JuanSanchezGarces/druvot-launcher
```

GitHub web UI has a 25MB upload limit — always use `gh release create` or `gh release upload` for the zip.

## Workflow: releasing a new launcher version

Only needed for `src/`, `assets/logo.png`, or `assets/icon.ico` changes — NOT for background image or changelog changes (those go live via `deploy.ps1` alone, no new launcher build/install needed).

```bash
# 1. Bump "version" in package.json
# 2. Build (from an Administrator terminal — npm scripts need npm.cmd directly, see below)
& "C:\Program Files\nodejs\npm.cmd" run build   # -> dist\druvot_launcher.exe

# 3. Publish as a GitHub Release
gh release create launcher-v<version> dist\druvot_launcher.exe --title "Druvot Launcher v<version>" --notes "..." --repo JuanSanchezGarces/druvot-launcher
```

Players/website should link to the stable alias, which always resolves to the newest release regardless of version:
`https://github.com/JuanSanchezGarces/druvot-launcher/releases/latest/download/druvot_launcher.exe`

Not currently code-signed — players see a Windows SmartScreen warning on first run (accepted tradeoff, no cert purchased).

## Running locally

```bash
# npm scripts won't run in PowerShell due to execution policy — use npm.cmd directly
& "C:\Program Files\nodejs\npm.cmd" start       # dev run
& "C:\Program Files\nodejs\npm.cmd" run build   # produces dist\druvot_launcher.exe
```

Or add `C:\Program Files\nodejs` to your PATH permanently to use `npm` directly.

## IPC surface (preload.js → renderer)

| Direction | Channel | Payload |
|---|---|---|
| main → renderer | `progress` | `{ percent: number, status: string }` |
| main → renderer | `changelog` | `Entry[]` |
| main → renderer | `background` | `string` (data URL, `data:image/png;base64,...`) |
| main → renderer | `ready` | `true \| 'offline'` |
| main → renderer | `error` | `string` |
| renderer → main | `launch-game` | — |
| renderer → main | `retry-update` | — |
| renderer → main | `window-minimize` | — |
| renderer → main | `window-close` | — |

## GitHub repository

- Repo: `https://github.com/JuanSanchezGarces/druvot-launcher` (public)
- Default branch: `master`
- `manifest.json`, `changelog.json` and `background.png` are **not** served from GitHub — they live on a VPS (`druvot.com.br/launcher/...`), deployed via `scripts/deploy.ps1` (SCP over SSH). This is deliberate: antivirus software commonly intercepts GitHub HTTPS connections, causing SSL failures in the launcher. Pushing to git records the change but does **not** make it live — only `deploy.ps1` does that.
- `client.zip` is hosted on GitHub Releases (tagged `client-vX.Y.Z`)
- `druvot_launcher.exe` (the installer itself) is hosted on GitHub Releases (tagged `launcher-vX.Y.Z`), linked from the website via the stable `releases/latest/download/druvot_launcher.exe` URL
