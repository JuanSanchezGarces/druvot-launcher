# Druvot Launcher

Game launcher for the Druvot OT server. Players download it once — the launcher handles all future client updates automatically.

---

## How it works

1. Player installs `druvot_launcher.exe` (the NSIS installer)
2. On every open, the launcher fetches `manifest.json` from `https://druvot.com.br/launcher/manifest.json`
3. Compares the remote version against the locally installed version
4. If versions match and the client exe exists → **JOGAR** button enables immediately
5. If update needed → downloads `client.zip` from the GitHub Release, verifies SHA-256, extracts
6. Clicking JOGAR launches `otclient_dx_x64.exe` (prefers DX, falls back to GL) and closes the launcher
7. If there is no internet connection but the client is already installed → shows a warning and still enables JOGAR
8. If the download fails → shows a **TENTAR NOVAMENTE** button

The client files live at `%APPDATA%\druvot-launcher\client\` on the player's machine.

## Project structure

```
assets/
  logo.png              — shown in the launcher titlebar
  background.png        — background image behind the changelog panel
  icon.ico              — auto-generated from logo.png, used by the installer
src/
  config.js             — all configurable values (URLs, server name, window size)
  main.js               — Electron main process: update engine, download, launch
  preload.js            — secure bridge between main and renderer
  renderer/
    index.html          — UI layout
    renderer.js         — progress bar, changelog, play button wiring
    style.css           — dark gold theme, 900×500px
scripts/
  generate-manifest.js  — run before every release to produce manifest.json
  deploy.ps1            — deploys manifest.json and changelog.json to the web server
changelog.json          — edit manually to add entries
manifest.json           — auto-generated by generate-manifest.js
```

## Releasing a client update

Do this every time you change anything in the OTClient folder.

### Step 1 — Zip the client folder

Zip the `Druvot` OTClient folder and copy it to a simple path:
```
Copy-Item "C:\path\to\Druvot.zip" C:\TFS\client.zip
```

### Step 2 — Generate the manifest

```
node scripts/generate-manifest.js <version> C:\TFS\client.zip
```

Example:
```
node scripts/generate-manifest.js 1.0.1 C:\TFS\client.zip
```

This creates/updates `manifest.json` with the new version, SHA-256 hash and download URL.

### Step 3 — Update the changelog

Edit `changelog.json` and add a new entry **at the top** of the array:

```json
[
  {
    "date": "2026-05-10",
    "version": "v1.0.1",
    "changes": [
      "Descrição da mudança 1",
      "Descrição da mudança 2"
    ]
  },
  {
    "date": "2026-05-06",
    "version": "v1.0.0",
    "changes": [
      "Lançamento do servidor Druvot!"
    ]
  }
]
```

### Step 4 — Deploy manifest and changelog to the web server

```
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1
```

This SCPs `manifest.json` and `changelog.json` to the VPS via SSH. Players will start seeing the new version immediately after this step.

### Step 5 — Upload the zip to a GitHub Release

> The GitHub web UI has a 25 MB upload limit — always use the CLI.

```
& "C:\Program Files\GitHub CLI\gh.exe" release create client-v1.0.1 C:\TFS\client.zip --title "Client v1.0.1" --notes "" --repo JuanSanchezGarces/druvot-launcher
```

Done. The next time any player opens the launcher it will detect the new version and download the update automatically.

## Updating the changelog only (no client changes)

If you made server-side changes and just want to announce them in the launcher without touching the client:

### Step 1 — Edit `changelog.json`

Add a new entry at the top of the array (see format in the release workflow above).

### Step 2 — Deploy

```
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1
```

That's it. No new manifest, no new GitHub Release needed. Players will see the updated changelog the next time they open the launcher.

## Building the installer

Run from an **Administrator terminal** (or with Developer Mode enabled in Windows Settings):

```
& "C:\Program Files\nodejs\npm.cmd" run build
```

Output: `dist\druvot_launcher.exe`

Share this file with players. They only need to download it once — all future client updates are handled automatically by the launcher.

> Players may see a Windows SmartScreen warning on first run ("Windows protected your PC"). They click **More info → Run anyway**. This is normal for unsigned apps.

## Running locally (development)

```
& "C:\Program Files\nodejs\npm.cmd" start
```

## Updating the launcher's own assets

| Asset | File | Notes |
|---|---|---|
| Titlebar logo | `assets/logo.png` | Any size, PNG |
| Background image | `assets/background.png` | Shown behind changelog, ideally 900×360px |
| App/installer icon | `assets/icon.ico` | Auto-generated from logo.png |

To regenerate `icon.ico` after changing `logo.png`:

```
node -e "const {default:p}=require('png-to-ico'),fs=require('fs');p('assets/logo.png').then(b=>fs.writeFileSync('assets/icon.ico',b))"
```

Then rebuild the installer.

## Hosting

| What | Where |
|---|---|
| `manifest.json` | `https://druvot.com.br/launcher/manifest.json` (VPS via deploy.ps1) |
| `changelog.json` | `https://druvot.com.br/launcher/changelog.json` (VPS via deploy.ps1) |
| `client.zip` | GitHub Releases, tagged `client-vX.Y.Z` |
| Launcher installer | Shared manually with players (Google Drive, Discord, website, etc.) |

> `manifest.json` and `changelog.json` are served from the VPS rather than GitHub because antivirus software commonly intercepts GitHub HTTPS connections, causing SSL failures in the launcher.

## `src/config.js` reference

| Field | Purpose |
|---|---|
| `SERVER_NAME` | Displayed in the titlebar |
| `GITHUB_OWNER` | Your GitHub username |
| `GITHUB_REPO` | Repository name |
| `MANIFEST_URL` | URL where manifest.json is served |
| `CHANGELOG_URL` | URL where changelog.json is served |
| `WINDOW_WIDTH/HEIGHT` | Launcher window size (default 900×500) |
