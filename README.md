# Druvot Launcher

Game launcher for the Druvot OT server. Players download it once — the launcher handles all future client updates automatically.

---

## How it works

1. Player installs `druvot_launcher.exe` (the NSIS installer)
2. On every open, the launcher fetches `manifest.json` and `changelog.json` from `https://druvot.com.br/launcher/`
3. It also fetches the background image in the background if a newer one is available (cached locally by hash, never blocks startup, silently falls back to the bundled image if unreachable)
4. Compares the remote client version against the locally installed version
5. If versions match and the client exe exists → **JOGAR** button enables immediately
6. If update needed → checks the game client isn't already running, then downloads `client.zip` from the GitHub Release, verifies SHA-256, extracts
7. Clicking JOGAR launches `otclient_dx_x64.exe` (prefers DX, falls back to GL) and closes the launcher
8. If there is no internet connection but the client is already installed → shows a warning and still enables JOGAR
9. If the download fails, or the game client is already open when an update is needed → shows a **TENTAR NOVAMENTE** button with a clear message

The client files live at `%APPDATA%\druvot-launcher\client\` on the player's machine.

## Project structure

```
assets/
  logo.png              — shown in the launcher titlebar (bundled, needs a rebuild to change)
  background.png        — background image behind the changelog panel (also deployed to the VPS — see "Updating the launcher's own assets")
  icon.ico              — auto-generated from logo.png, used by the installer
src/
  config.js             — all configurable values (URLs, server name, window size)
  main.js               — Electron main process: update engine, download, launch
  preload.js            — secure bridge between main and renderer
  renderer/
    index.html          — UI layout
    renderer.js         — progress bar, changelog, play button wiring
    style.css           — dark gold theme, 900×500px
scripts/
  generate-manifest.js  — run before every release to produce manifest.json
  deploy.ps1            — deploys manifest.json, changelog.json and background.png to the web server
changelog.json          — edit manually to add entries (supports simple markup — see below)
manifest.json           — auto-generated by generate-manifest.js; also holds the background image's URL/hash
```

## Releasing a client update

Do this every time you change anything in the OTClient folder.

### Step 1 — Zip the client folder

Zip the `Druvot` OTClient folder and copy it to a simple path:
```
Copy-Item "C:\path\to\Druvot.zip" C:\TFS\client.zip
```

### Step 2 — Generate the manifest

```
node scripts/generate-manifest.js <version> C:\TFS\client.zip
```

Example:
```
node scripts/generate-manifest.js 1.0.1 C:\TFS\client.zip
```

This creates/updates `manifest.json` with the new version, SHA-256 hash and download URL.

### Step 3 — Update the changelog

Edit `changelog.json` and add a new entry **at the top** of the array. Each string in `changes` supports a small markup syntax:

| Syntax | Renders as |
|---|---|
| `"# Título"` | Section heading |
| `"**texto**"` | Bold (works inside any line) |
| `"- item"` | Bullet |
| `"  - item"` (2+ leading spaces) | Sub-bullet |
| `""` | Blank spacer |
| anything else | Plain text line |

```json
[
  {
    "date": "2026-05-10",
    "version": "v1.0.1",
    "changes": [
      "# Novidades",
      "**Novo evento de Rifts**",
      "  - Detalhe 1",
      "  - Detalhe 2",
      "",
      "- Descrição da mudança 2"
    ]
  },
  {
    "date": "2026-05-06",
    "version": "v1.0.0",
    "changes": [
      "Lançamento do servidor Druvot!"
    ]
  }
]
```

> This markup only renders on launcher builds from `launcher-v1.0.0` onward. Players still on an older launcher just see the raw `#`/`**`/`-` characters as plain text — harmless, just less polished until they update.

### Step 4 — Deploy manifest and changelog to the web server

```
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1
```

This SCPs `manifest.json`, `changelog.json` and `background.png` to the VPS via SSH. Players will start seeing the new version immediately after this step.

### Step 5 — Upload the zip to a GitHub Release

> The GitHub web UI has a 25 MB upload limit — always use the CLI.

```
& "C:\Program Files\GitHub CLI\gh.exe" release create client-v1.0.1 C:\TFS\client.zip --title "Client v1.0.1" --notes "." --repo JuanSanchezGarces/druvot-launcher
```

Done. The next time any player opens the launcher it will detect the new version and download the update automatically.

## Updating the changelog only (no client changes)

If you made server-side changes and just want to announce them in the launcher without touching the client:

### Step 1 — Edit `changelog.json`

Add a new entry at the top of the array (see format in the release workflow above).

### Step 2 — Deploy

```
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1
```

That's it. No new manifest, no new GitHub Release needed. Players will see the updated changelog the next time they open the launcher.

> `deploy.ps1` always pushes all three files (`manifest.json`, `changelog.json`, `background.png`) together — harmless even if only one changed.

## Releasing a new launcher version

Do this only when you change launcher **code or bundled assets** (`src/`, `assets/logo.png`, `assets/icon.ico`). Background image and changelog changes do **not** need any of this — see "Updating the launcher's own assets" below.

### Step 1 — Bump the version

Update `"version"` in `package.json`.

### Step 2 — Build

Run from an **Administrator terminal** (or with Developer Mode enabled in Windows Settings):

```
& "C:\Program Files\nodejs\npm.cmd" run build
```

Output: `dist\druvot_launcher.exe`

### Step 3 — Publish a GitHub Release

```
& "C:\Program Files\GitHub CLI\gh.exe" release create launcher-vX.Y.Z dist\druvot_launcher.exe --title "Druvot Launcher vX.Y.Z" --notes "..." --repo JuanSanchezGarces/druvot-launcher
```

Players always download the same stable URL, which redirects to whichever release is newest — it never needs to change on the website:

```
https://github.com/JuanSanchezGarces/druvot-launcher/releases/latest/download/druvot_launcher.exe
```

Link to that URL from `druvot.com.br`'s download page. Existing players on an older launcher build keep working fine (see "How it works") — only players who grab the new installer get the latest launcher-side features.

> Players may see a Windows SmartScreen warning on first run ("Windows protected your PC"). They click **More info → Run anyway**. This is normal for unsigned apps (we're not currently code-signing).

## Updating the launcher's own assets

| Asset | File | Rebuild needed? |
|---|---|---|
| Background image | `assets/background.png` | **No** — deployed like the changelog, see below |
| Titlebar logo | `assets/logo.png` | Yes — bundled into the installer |
| App/installer icon | `assets/icon.ico` | Yes — auto-generated from logo.png |

### Background image (no rebuild, no player redownload)

The launcher fetches this live from the VPS and caches it locally by hash, so changing it doesn't require a new installer.

1. Replace `assets/background.png`. Ideal size: **1800×720px** (2x of the 900×360 display area, for crisp rendering on HiDPI screens), aspect ratio 2.5:1, ideally under ~1–2MB. Note the left ~380px of the display area sits behind the semi-transparent changelog panel — keep important detail toward the right/center.
2. Recompute its hash:
   ```
   powershell -Command "(Get-FileHash 'assets\background.png' -Algorithm SHA256).Hash.ToLower()"
   ```
3. Paste that hash into `manifest.json`'s `background.hash` field.
4. Deploy:
   ```
   powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1
   ```

Players see the new background the next time they open the launcher — no new installer needed. (If the hash in `manifest.json` doesn't match the deployed file, the launcher silently keeps showing the old background — it never applies an unverified download.)

### Logo / icon (rebuild required)

`assets/logo.png` and `assets/icon.ico` are bundled directly into the installer.

To regenerate `icon.ico` after changing `logo.png`:

```
node -e "const {default:p}=require('png-to-ico'),fs=require('fs');p('assets/logo.png').then(b=>fs.writeFileSync('assets/icon.ico',b))"
```

Then release a new launcher version (see "Releasing a new launcher version" above) — players need to download the new installer to see the change.

## Hosting

| What | Where |
|---|---|
| `manifest.json` | `https://druvot.com.br/launcher/manifest.json` (VPS via deploy.ps1) |
| `changelog.json` | `https://druvot.com.br/launcher/changelog.json` (VPS via deploy.ps1) |
| `background.png` | `https://druvot.com.br/launcher/background.png` (VPS via deploy.ps1) |
| `client.zip` | GitHub Releases, tagged `client-vX.Y.Z` |
| Launcher installer | GitHub Releases, tagged `launcher-vX.Y.Z` — linked from `druvot.com.br`'s download page via the stable `releases/latest/download/druvot_launcher.exe` URL |

> `manifest.json` and `changelog.json` are served from the VPS rather than GitHub because antivirus software commonly intercepts GitHub HTTPS connections, causing SSL failures in the launcher.

## `src/config.js` reference

| Field | Purpose |
|---|---|
| `SERVER_NAME` | Displayed in the titlebar |
| `GITHUB_OWNER` | Your GitHub username |
| `GITHUB_REPO` | Repository name |
| `MANIFEST_URL` | URL where manifest.json is served |
| `CHANGELOG_URL` | URL where changelog.json is served |
| `WINDOW_WIDTH/HEIGHT` | Launcher window size (default 900×500) |
